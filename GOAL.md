# Fluxgrade execution goal

Build and prove the first real agent-first Fluxgrade mission, then continue toward the complete SaaS in dependency order.

## Immediate goal

A fresh player can start `checkout-latency`, enter a real local repository, use their normal coding agent to investigate a running stateful system, deploy through Fluxgrade, receive a durable midstream requirement change, adapt, submit, receive an external hidden evaluation, and replay the evidence after teardown.

## Operating method

- `AGENTS.md` is mandatory.
- The executable plan is the Beads graph rooted at `fluxgrade-c90`.
- Use `bvr --robot-next`, `--robot-triage`, `--robot-plan`, and `--robot-insights` in robot mode.
- Claim one ready leaf bead at a time.
- Implement tests before behavior where practical.
- Exercise the real artifact before closing a bead.
- Run a reality check at each major gate.
- Flush Beads, commit, push, and verify the remote after verified work.
- Never commit secrets or the raw untracked brainstorm transcript.

## Autonomous OMP role

OMP may implement ready beads autonomously. It should continue through the critical path while tests and proof pass. When the local mission becomes playable, OMP must enter the generated candidate repository as a player, attempt the mission using only candidate-visible context, and record the playtest evidence under `docs/playtests/`.

A tool or provider credential blocker should not be disguised as completion. Record the blocker in its bead, leave it open, and continue only where dependencies permit.

## Completion boundary

The immediate goal is not complete until all of these are real and exercised:

- local candidate repository;
- stateful runtime;
- separate evaluator;
- midstream event delivery;
- credential-brokered deployment;
- frozen clean submission;
- provenance-aware report;
- deterministic replay;
- at least one complete OMP playthrough;
- current trailer still passing;
- changes pushed and remotely verified.
